## Первый запуск

1. Дождитесь зелёного запуска **Actions → Setup and deploy**. Он копирует зафиксированный исходный код в этот репозиторий, создаёт отдельную ветку `gh-pages` с шестью пустыми экранами и публикует приложение в GitHub Pages.
2. Если шаг Configure Pages просит включить Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**, затем повторно запустите workflow. Если Actions запрещены настройками аккаунта, разрешите их для этого репозитория.
3. В админке подключите fine-grained personal access token GitHub: владелец `maxzakir-glitch`, **только репозиторий SushiOrdo**, Repository permissions → **Contents: Read and write**. Создайте его на https://github.com/settings/personal-access-tokens/new . Не выдавайте доступ к исходному кафе. Вставляйте токен только в защищённое поле админки, не в чат и не в URL. GitHub-подключение ассистента автоматически не авторизует браузер админки.
4. Введите свои данные, загрузите фотографии, переместите плашки и нажмите **Сохранить**. Дождитесь **«✓ Записано в SushiOrdo»**. Черновик на устройстве и публикация на ТВ — разные состояния. Без токена данные остаются черновиком.
5. На каждом из шести ТВ откройте его отдельный адрес. Игрок проверяет опубликованную версию каждые 10 секунд. Реальная доставка зависит от сети и кэшей GitHub CDN, мгновенное обновление не гарантируется.

## Что исправлено

- Полная изоляция хранилища, токена, адресов и данных от первого кафе. Старые ключи localStorage не импортируются.
- Черновик в IndexedDB, включая фото при работе без подключения. Ошибки сохранения видны, можно скачать JSON-резервную копию. Не очищайте данные браузера: это удалит локальные черновики.
- «Обновить данные» больше не удаляет локальные данные. Перед заменой неопубликованных правок требуется подтверждение.
- Подключение проверяет новый введённый токен и правильный GitHub API `/user`, а не старый токен и не `/repos/.../user`.
- Публикации сериализованы. Новые правки во время запроса ставятся в следующую очередь. Старая версия не может молча перезаписать новую: проверяются revision и GitHub SHA; конфликт требует решения пользователя. После неоднозначной сетевой ошибки результат проверяется, запись не повторяется вслепую.
- ТВ используют только опубликованные данные и свой отдельный кэш, а не черновик редактора. Неверный ID экрана показывает ошибку, а не содержимое ТВ1. При сбое сети остаётся последняя загруженная публикация.
- Фото публикуются отдельными файлами, чтобы не раздувать menu.json и localStorage. Офлайн-фото переносятся в файлы при публикации. Медиа до 45 МБ.
- Пересборка сайта никогда не сбрасывает рабочее меню: код в `main`, меню/медиа в `gh-pages`, чтение с отдельного raw-адреса. Старый скрипт ручного деплоя отключён.

## Безопасность и ограничения

Репозиторий, опубликованные блюда и загруженные медиа публичны, как и исходный сайт. Не загружайте персональные данные, токены, пароли или внутренние документы. Токен хранится только в браузере администратора; телевизорам он не передаётся. Работайте на доверенном устройстве, не делитесь его профилем браузера. Для отзыва доступа удалите/отзовите токен в настройках GitHub. Редактируйте с одного устройства за раз: вкладки на одном устройстве блокируются, разные устройства защищены проверкой конфликта при записи.

GitHub Raw/CDN — не специализированный realtime-бэкенд. Опрос 10 секунд не означает SLA в 10 секунд. При нестабильном интернете проверьте сообщение статуса на ТВ. Для строгой гарантии доставки и приватных меню понадобится отдельный backend/хостинг.

## Разработка и проверки

`npm ci`, `npm run dev`, `npm run build`. Базовый путь строго `/SushiOrdo/`, маршрутизация через `#/...` для корректной перезагрузки статического сайта.

Локально проверены в Chromium с имитацией GitHub API (без изменения реальных меню): первая правка; перемещение и сохранение координат; перезагрузка с неопубликованным черновиком; отказ от замены через «Обновить данные»; изоляция ТВ от черновика; блокировка второй вкладки; подключение нового токена; публикация и повторная загрузка; маршруты ТВ1–ТВ6; ошибка вместо ТВ1 при неизвестном ID; отказ от перезаписи облачной версии; видимая ошибка при отказе записи. Это не заменяет проверку настоящего токена и шести физических ТВ.
